# 分位舍入命运纪要（封板）

- 产品：保证金笼（母仓单文件库 `data/app.db`）
- 封板日：2026-11-24
- 背景缺陷：六位小数入金/入笼/解笼直接落库，冻结累计漂移；对账容差 0.02 致差一厘仍亮绿；列表页与账户页口径打架。
- 根因：金额落库路径未统一分位舍入规则。

## 一、分位舍入命运（择一：甲路径）

**择定甲路径，乙路径与第三路线全面禁止，本纪要当日封板，不再复议。**

1. 约定分位：**分（2 位小数）**，舍入法 **ROUND_HALF_UP**，唯一实现点 `backend/money.py::to_fen`。
2. 一切写入名册（开户入金、手工入金、入笼冻结、解笼拨付、罚没）**落库前必须统一到分**；精度侧只有写入侧这一侧，读侧不再另设容差口径，两边不得混用。
3. 统一到分后金额为零（零改）的写入**拒写**，已动笔的草稿**原子回滚**（业务写与锁登记分账：业务异常即 rollback，仅锁释放入库）。
4. 对账页为甲路径的读侧投影：同一分位口径**零容差**判定（仅容忍浮点 epsilon 1e-6），存量分位漂移行必须亮红灯并显式标出「分位不齐」，禁止只改误差提示文案充数。
5. 偏航处理：任何写入路径绕过 `to_fen` 落库金额，记「分位舍入偏航」并拒写。

## 二、并发争用口径（与分位命运分述，不并段）

1. 同一当事人的金额写入（入金、入笼、解笼、罚没）**必须抢账户锁** `bond:{party_key}`；解笼/罚没先抢笼锁 `cage:{id}` 再抢账户锁，全仓顺序一致防死锁。
2. 后到争用：只记 `contention_log` 不写业务，争用登记**须落库可复现**（锁冲突即提交登记，不随业务回滚）。
3. 争用复现须脚本化：双会话/双请求同时写同一当事人金额，后到方 409 且争用记录可查（见 `tests/test_amount_contention.py`）。

## 三、禁止事项（复述约束）

- 禁止甲乙混用（混用则差厘假绿瞒目）。
- 禁止第三路线写法。
- 禁止只改对账页误差提示文案。
- 禁止无失败测前提下改舍入实现。
